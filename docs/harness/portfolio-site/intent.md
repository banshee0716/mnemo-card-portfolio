# portfolio-site — intent

G1：owner 於 2026-10-19 核可（對話中逐項裁定）；G1 挑戰者為全新工作階段的 opus（2026-10-19）。
本檔是公開版，只描述本網站；owner 裁定的原始紀錄保存在主程式的私有儲存庫。

## 使用者得到什麼

學術讀者與求職讀者打開一個公開網站，由淺入深看懂 Mnemo-Card：先讀到它解決什麼問題、做出什麼成果，
再分支到學習科學依據與產品怎麼用。學習科學文章從此只在本站；操作文件只在文件站
（`https://banshee0716.github.io/mnemo-card-docs/`）。

## owner 裁定（2026-10-19）

1. **核心目標**：作品集展示，放在獨立的網站。不服務這個目標的項目一律延後。
2. **分工與正式版本**：學習科學文章（與之後的開發規劃）以本站為準；操作文件以文件站為準，只此一份。
3. **技術與託管**：比照文件站——獨立的**公開** GitHub 儲存庫 `mnemo-card-portfolio`，Astro 靜態建置，
   GitHub Actions 部署到 GitHub Pages，網址 `https://banshee0716.github.io/mnemo-card-portfolio/`。
4. **版型**：同一個 Astro 專案——作品集首頁自訂（「問題 → 成果 → 分支」敘事），共用文件站的樣式變數；
   文章頁用 Starlight（側欄、文章目錄、搜尋）。
5. **第一版頁面（9 頁）**：作品集首頁 1 頁＋學習科學導讀 1 頁與文章 6 篇（自文件站搬入）＋
   「產品怎麼用」摘要 1 頁（幾張截圖，連到文件站）。
6. **操作文件不複製**：只放摘要並連回文件站。兩個儲存庫的完整備份以定期打包封存處理，不在網站上放第二份
   （不屬本切片）。
7. **讀者**：學術與求職兼顧；首頁先講問題與成果，再分支到學術依據與產品。
8. **公開深度**：產品畫面、功能，加上不含內部細節的成果數字。不寫主機位置、後端或服務名稱、資料庫結構；
   開發方法只用一段文字講概念，不放內部文件或審查原文。spec 須逐條列出允許公開的白名單（不得用形容詞帶過）；
   `check:public` 沿用文件站的機制，允許清單從空開始。
9. **文件站善後（第二個切片）**：本站上線、Pages 部署成功後才開始，在文件站儲存庫進行。
10. **等級**：LOW，採 owner 輕量流程（G2A＋G2B 由全新 opus 一次合審；G6A＋G6B 合一輪 Codex）。
    主要風險＝公開內容白名單，列入品質線。

## 範圍

- Astro＋Starlight、繁中、品牌樣式（文件站 CSS 變數、Noto TC、Logo）、自訂首頁、搬入 7 頁學習科學 MDX
  （文中 3 處連到〈第一次使用〉的相對連結改為文件站絕對網址）、摘要頁、Pagefind 搜尋、GitHub Actions 部署、
  `check:public`、改寫（非照搬）文件站的 Playwright 測試：站內連結、手機寬度、鍵盤與無障礙，涵蓋全部 9 頁含自訂首頁；
  首頁是否進搜尋在 spec 決定。

## 非目標

- 開發規劃／路線圖頁（之後另開切片，先決定哪些規劃可公開）；操作文件複本；跨儲存庫同步；
  文件站舊網址轉址；產品本身的任何改動；自訂網域；技能下載；後端、CMS、多語、版本切換；封存備份的自動化。

## 規模數字

- 頁數：9。更新頻率：低（學習科學文章偶爾修訂）。截圖：文件站現有約 2.1 MB，摘要頁只取其中數張。
- 讀者量：不大量散布，靜態站無容量問題。
